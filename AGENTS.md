- Survival map uses MapLibre + OpenFreeMap with all symbol/building layers stripped (TerrainMap.tsx); why: game map must show no real-world brand/place labels. Recipes are locked behind techs in src/lib/survival/tech.ts; why: players learn toolmaking progressively.
- Exploration login uses a validated same-origin returnTo and the existing persisted, auto-refreshed auth session; why: returning players resume exploration without storing passwords or changing guest room access.
- Survival planning uses a server-only streaming AI Gateway Edge Function; regenerate shared rules with `bun scripts/sync-survival-ai-rules.ts` before deploying it so recommendations use the same recipes and technologies as gameplay.
- Survival AI remains guest-accessible with a server-side request throttle; provider/credit blocks persist in server-only access state until access is restored and the block is explicitly cleared, preventing reloads from bypassing denials.
- `/world` and `/play/survival` use actual GPS survival with no mock fallback; `/play/survival-sim` retains isolated simulator saves so test movement cannot contaminate real GPS progress.
- Survival resource coordinates derive from the shared geographic seed, not the current camera/player center; GPS signal quality gates all real-world interactions and base actions to prevent remote or stale-location play.
- Survival GPS progression reuses progression.ts and quests.ts through worldProgress.ts; persist counters and quest index with the world save, and claim rewards only at a GPS-valid base to avoid duplicate rewards or divergent rules.
- Keep the survival screen's Fast Refresh reset directive: custom world/GPS hook updates can change hook order across modules, so preview refresh must remount from the persisted save rather than reuse stale React hook queues.
- Survival terrain colors come from global CSS tokens; visual-only scenery uses a separate geographic seed salt and one canvas beneath fog, so map detail never changes resource positions or intercepts interactions.
- Character animations are horizontal sprite-sheet strips stored in the private survival-sprites bucket and read via signed URLs; why: workspace blocks public buckets, and the game falls back to the bundled sprite when no sheet exists.
- Real terrain zones (riverside/highland/plains) are sampled from rendered map surfaces and stored per coarse cell in the world save (first sample wins); why: resource ratios must stay stable for a place while still reflecting real geography.
- Survival cloud saves live in public.survival_saves (one row per user, full WorldSave JSON); sync only in real-GPS mode via useSurvivalWorld cloudSync — the newer lastTickAt wins on login, and changes upload after a 2.5s debounce; why: cross-device restore without touching the isolated simulator save.
- Survival multiplayer uses one realtime presence room per ~1km cell with throttled position tracking (5m/3s, 20s heartbeat) and tiny broadcast events; why: dozens of nearby players must not flood realtime traffic as in the 35-player tag game.
- Survival landmarks come from an invisible POI probe layer (no labels drawn) and are classified in src/lib/survival/landmarks.ts; claim limits (cooldown, per-place and global daily caps) live in the world save so cloud sync carries them. Park cells are sampled once per zone cell and multiply creature density.
