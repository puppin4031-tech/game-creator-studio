# 콜로니온 보안 강화 — 단계별 진행

한 번에 다 바꾸지 않고, 게임 체감에 영향이 적은 것부터 3단계로 진행합니다. 각 단계가 끝나면 확인 후 다음 단계로 넘어갑니다.

## 1단계: 개인정보·요금 보호 (이번 작업)
1. **보안 점검 먼저**: 데이터베이스 보안 스캔과 테이블별 접근 규칙을 확인하고, 발견된 문제를 목록으로 정리해 우선 수정합니다.
2. **거점 위치 숨기기**: 다른 유저에게 보내는 내 위치/거점 좌표를 약 50m 격자로 뭉개서 보냅니다. 내 화면에서는 정확한 위치를 그대로 씁니다. 거점(집) 근처에서는 다른 유저에게 정확한 거점 위치가 절대 나가지 않게 합니다.
3. **AI 요금 방어**: 생존 AI 요청에 하루 사용 한도(로그인 유저 기준)를 추가하고, 입력 길이를 서버에서 제한합니다. 기존 30초 간격 제한은 유지합니다.
4. **저장 데이터 검증**: 클라우드 저장 시 서버에서 저장 데이터 크기와 형식, 수치 상한(체력·허기·아이템 개수 등)을 검사해 비정상 값을 거부합니다.

## 2단계: GPS 조작 방어
1. 이전 위치 대비 이동 속도를 계산해 초속 15m 이상 순간이동은 상호작용(채집·전투·보상)에서 무시합니다.
2. 같은 판정을 서버 저장 시에도 적용해, 저장된 마지막 위치·시각 기준으로 비정상 진행을 거부합니다.
3. 위반이 반복되면 일정 시간 보상 수령을 막고 안내 토스트를 띄웁니다.

## 3단계: 서버 권한 강화
1. 보상 수령(랜드마크·퀘스트·우두머리 드롭)을 서버 함수로 옮겨, 화면 쪽 조작으로 보상을 늘릴 수 없게 합니다.
2. 이후 채집·제작도 순차적으로 서버 확인 방식으로 전환할지 1~2단계 결과를 보고 결정합니다.

## 하지 않는 것
- 익명 로그인: 플랫폼 정책상 익명 가입을 쓰지 않습니다. 술래잡기 게스트 링크 참여는 기존 방식 유지.
- "개발자 도구 자체 차단": 브라우저에서는 막을 수 없으므로, 대신 서버 검증으로 조작 효과를 무력화합니다.

## 기술 메모
- 1단계: security scan + RLS 점검, `useSurvivalPresence` 송신 좌표 snap(50m), `survival_saves` 검증 트리거(payload 크기·스키마·상한), Edge Function에 user별 일일 quota 테이블(GRANT+RLS 포함) 및 zod 입력 제한.
- 2단계: 순수 함수 `antiSpoof.ts`(속도 계산) + 테스트, 저장 트리거에서 lastTickAt/위치 비교.
- 3단계: SECURITY DEFINER RPC로 보상 claim, 클라이언트는 결과만 반영.
- 각 규칙(15m/s, 50m 격자, 일일 한도)은 테스트로 고정.
